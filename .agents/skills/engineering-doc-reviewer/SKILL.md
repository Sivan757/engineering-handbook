# Engineering Doc Reviewer

使用场景：文章发布前、PR 审查、内容例行更新。

## 审核顺序

1. 阅读 `AGENTS.md`、`docs/team/writing-guide.md` 和目标文章。
2. 确定其读者、目标及 Diátaxis 文档类型。
3. 逐项核对核心技术事实、命令、API、版本和引用的来源。
4. 对教程核对操作、预期结果、前提条件和练习。
5. 对指南核对错误处理；对参考资料核对条目准确性。
6. 审核公开安全：凭据、生产地址、隐私数据、内部架构。
7. 核对导航、相对链接、术语一致性和可读性。
8. 运行 `npm run docs:build`，写明是否真实执行。

## 输出格式

- Blocker：阻止发布的事实错误、安全风险、不可执行内容。
- Major：目标不清、结构混乱、关键示例缺失。
- Minor：措辞、导航、术语一致性等。
- Verified：实际执行的命令及可观察结果。
- Unverified：无法验证的事项与原因。

审查时给出明确文件路径和修改建议。不得将“未验证”写成“通过”。
