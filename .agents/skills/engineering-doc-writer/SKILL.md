# Engineering Doc Writer

使用场景：新增文档、扩展课程、为常见问题补充解释。

## 流程

1. 阅读 `AGENTS.md` 与 `docs/team/writing-guide.md`。
2. 识别读者角色、学习级别、单篇核心任务和已有相近文章。
3. 从 tutorial、how-to、reference、explanation 中选择一种类型。
4. 使用仓库 `templates/` 内相应模板，不混合多种文章目标。
5. 先列可验证的完成标准，再安排说明、步骤、示例。
6. 优先使用公开、脱敏、可重现的真实示例。
7. 区分正式规范与建议稿，不捏造技术事实或执行结果。
8. 补上相关导航和交叉链接，并运行构建。

## 完成条件

- 新人不需要额外背景就能理解首次出现的术语。
- 教程提供可执行步骤和预期结果；参考资料可快速查询。
- 文章无内部信息泄露，链接有效且标注适用技术版本。
- 没有与已有章节无意义重复。

对于尚未确定的事实，明确标注待核实，不得编造成定论。
