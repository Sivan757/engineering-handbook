# 如何排查 API 请求错误

**适用情形：** 请求无法得到预期结果、返回 4xx/5xx，或根本没有收到 HTTP 响应。

## 第一步：区分网络错误与 HTTP 错误

~~~bash
curl -i --max-time 10 'https://httpbin.org/status/404'
~~~

如果收到 `HTTP/2 404` 或 `HTTP/1.1 404`，说明服务器给出了 HTTP 响应。

如果出现 `Could not resolve host`、连接失败或超时，应先判断 DNS、代理、网络连接及服务器状态。

## 第二步：记录最小事实

记录请求方法、URL 路径、查询参数、响应状态码、错误消息和时间。

**不要复制完整的 Authorization 头、Cookie 或生产业务数据到公开 Issue。**

## 第三步：按状态码排查

| 状态 | 优先排查 |
| --- | --- |
| 400 | 参数格式、必填字段、Content-Type |
| 401 | 是否登录、凭据是否有效 |
| 403 | 当前身份是否有资源权限 |
| 404 | URL、路由或目标资源是否存在 |
| 409 | 是否发生版本或状态冲突 |
| 429 | 限流策略与重试间隔 |
| 500 | 服务端日志、异常追踪、请求 ID |
| 502/503/504 | 网关、上游依赖、服务状态与超时 |

详情参阅 [HTTP 状态码速查](/reference/http-status)。

## 第四步：最小化复现

1. 用公开测试数据复现问题。
2. 去掉无关参数，保留复现所需的最少输入。
3. 比较成功和失败请求的差异。
4. 依据服务端日志或追踪信息缩小范围。

## 完成标准

能够提供“预期结果、实际结果、复现步骤、已尝试的方法和下一步排查方向”。

此指南提供通用定位路径。具体系统的权限、错误码和运维流程以其正式文档为准。
