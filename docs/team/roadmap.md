# 内容建设路线图

**长期目标：** 同时服务知识学习、实际工作和团队协作。先建立公共知识，再根据真实问题扩展专业内容。

## 内容领域

| 领域 | 建设方向 |
| --- | --- |
| 通识基础 | 计算机、互联网、HTTP、API、数据与数据库 |
| AI 素养 | LLM、Prompt、模型 API、RAG、Agent、MCP、安全 |
| 产品与体验 | 用户研究、需求分析、PRD、原型、验证 |
| 软件开发 | 编程基础、前后端、Git、调试、数据建模 |
| AI 工程 | AI 编程、Skills、Tool Use、Agent 工作流 |
| 软件工程 | 系统设计、测试、质量、安全、性能 |
| DevOps | Linux、容器、CI/CD、可观测性、发布与回滚 |
| 产研协作与专题 | 需求评审、技术沟通、ADR、案例、前沿研究 |

**知识按领域归档，课程按角色引用。** 课程不复制原始文章。

## 阶段规划

| 阶段 | 交付范围 | 完成标准 |
| --- | --- | --- |
| 第 1 阶段 | 写作规范、学习路径、API 教学样板 | 四类文档可对照使用 |
| 第 2 阶段 | AI 素养和提示词课程 | 产品、研发新人完成实践题 |
| 第 3 阶段 | 产品工作流与软件开发入门 | 不同岗位有可执行入门路径 |
| 第 4 阶段 | 研发质量、AI 工程、DevOps、案例 | 按项目问题扩展，形成持续更新机制 |
| 后续 | 团队已采纳的规范和流程 | 有评审记录、负责人和适用范围 |

## 候选文章池

- AI：LLM 与 Token；上下文与提示词；Agent、Tool 与 Skill；模型 API 调用。
- 产品：用户问题与解决方案；PRD 最小结构；原型设计；需求评审。
- 工程：Git 与 PR 实操；接口契约；自动化测试；AI 代码验证。
- 协作：技术问题描述；迭代计划；设计决策记录；故障复盘。

按“真实提问频率 × 对交付的影响 × 是否有合适作者”排序。没有依据时不杜撰频率数据。

## 维护机制

1. 用 GitHub Issue 收集真实问题和待补充的文章。
2. 每篇文章指定读者、目标、作者和文档类型。
3. 在 Pull Request 中审核事实、示例、术语和安全风险。
4. 让不熟悉主题的读者尝试练习，收集失败点。
5. 修改文章后更新导航和相关学习路径。
