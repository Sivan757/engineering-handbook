# 文档贡献指南

**原则：** 每个 Pull Request 解决一个明确的读者问题，优先改进真实有人问过的内容。

## 添加或修改文章

1. 搜索现有内容，避免重复。
2. 选择读者、目标、难度和文章类型。
3. 使用仓库根目录 `templates/` 中对应的模板。
4. 提供脱敏且可复现的例子，以及来源和适用版本。
5. 修改 VitePress 导航或相关学习路径。
6. 运行 `npm run docs:build` 并提交 PR。

详细规则见 [写作规范与文章类型](/team/writing-guide)。

## 提交前

- **事实：** API、命令、参数、状态码和参考来源准确。
- **可用：** 教程包含可执行步骤、预期输出和完成标准。
- **定位：** 文章有明确类型和目标读者，不重复现有内容。
- **安全：** 不公开客户信息、密钥、生产日志、内部域名或架构。
- **状态：** 建议稿不得被描述为已生效的团队制度。

## 修改与弃用

文章结论发生变化时，记录新版本、兼容性和相关迁移指南。旧的技术决策记录保留历史原因，不直接覆写决策背景。

## 使用 AI 协助

仓库提供 `engineering-doc-writer` 和 `engineering-doc-reviewer` 两个 Skills。生成内容必须由人核对。

未实际运行的命令和测试不能写成“已验证”。
