# 提示词改写练习

**完成后你可以：** 为产品、研发和测试任务编写清晰提示词，并比较迭代前后的结果。

## 准备

选择任意获准使用的 AI 工具。全部示例使用虚构任务，不包含企业真实信息。

## 练习一：从模糊到清楚

先输入：

~~~text
帮我优化登录功能。
~~~

阅读回答，记录有哪些假设，例如登录方式、目标用户、错误表现。

再输入：

~~~text
你是产品分析助手。
背景：练习用的任务管理网站，用户使用邮箱和密码登录。
目标：降低“密码输错后不知道下一步”的用户困惑。
约束：不要修改认证技术方案，不涉及真实用户信息。
输出：问题陈述、两个交互方案、各自风险、验收标准。
请把尚不明确的条件放到“待确认”栏。
~~~

**比较点：** 第二次是否减少了无依据的技术方案？是否能直接进入评审？

## 练习二：给出输入和输出格式

~~~text
请对以下虚构反馈分类：
1. “登录后页面一直转圈。”
2. “找不到创建任务按钮。”
3. “导出的日期格式不统一。”

只能使用“性能”“可用性”“数据质量”三个类别。
返回 Markdown 表格：编号、类别、理由、需要补充的信息。
不确定时说明原因，不要捏造根因。
~~~

**验收：** 表格中有三行输入，每条都有理由。类别属于约定集合。

## 练习三：把输出变成任务

~~~text
根据练习二的反馈，挑选“找不到创建任务按钮”。
请写：
1. 一个用户故事；
2. 影响范围和待确认条件；
3. 四条可测试的验收用例。
不能假设已有的原型、指标或用户研究结论。
~~~

**验收：** 每个用例能回答“给定什么条件、做什么操作、看见什么结果”。

## 复盘表

| 指标 | 第一次 | 改写后 |
| --- | --- | --- |
| 目标清楚 | 是/否 | 是/否 |
| 有无编造背景 | 是/否 | 是/否 |
| 输出是否符合格式 | 是/否 | 是/否 |
| 是否可以直接验收 | 是/否 | 是/否 |

不同模型的输出可能变化。比较时尽量使用相同模型与相同输入条件。

**完成标准：** 能举出两处改进，并说明改进来自哪些补充条件。
