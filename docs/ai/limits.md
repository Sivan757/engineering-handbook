# AI 的能力、幻觉与局限

**一句话：** AI 可以加速分析、写作和编程，但“看起来合理”不代表“事实正确”。

## 擅长做什么？

- 将模糊想法整理为清晰结构。
- 草拟文案、用户故事和测试用例。
- 解释技术概念、提供备选方案。
- 在有工具授权的环境里协助执行重复操作。

## 哪些地方容易出错？

| 问题 | 例子 | 怎么验证 |
| --- | --- | --- |
| 事实幻觉 | 编造不存在的 API | 查官方文档 |
| 过度推断 | 未读日志就断言故障根因 | 查真实日志与指标 |
| 版本混淆 | 混用新旧 SDK 参数 | 查当前版本文档 |
| 遗漏边界 | 忽略权限与失败分支 | 设计边界测试 |
| 格式正确但逻辑错 | JSON 合法，但金额计算错误 | 业务断言与人工审核 |

## 三种证据必须分清

**模型声称：** “我已经运行测试。”

**工具输出：** 实际工具有退出码和日志。

**可复现验证：** 其他人按相同条件能获得对应结果。

只有第一种，不能标记为“测试通过”。

## 一个可复用的核对方法

1. 找出回答中影响决策的关键结论。
2. 标记哪些结论有来源，哪些只是推断。
3. 通过官方资料、实际工具或测试核对。
4. 对无法核实的部分说明不确定性。
5. 将事实和建议分别写进最终结果。

## 练习

让模型列出“某个你熟悉的开源软件支持的三个功能”。逐条查官方资料，记录“已证实、未证实、错误”。

**完成标准：** 不以模型自身重复确认作为证据。
