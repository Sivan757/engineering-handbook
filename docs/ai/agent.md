# Workflow 与 Agent 的区别

**一句话：** Workflow 的步骤由程序预先安排；Agent 可以根据任务和工具结果动态选择下一步。

## 从最简单的方案开始

**单次模型调用：**

~~~text
输入会议纪要 → 模型生成摘要 → 人工审核
~~~

**固定 Workflow：**

~~~text
输入纪要 → 提取行动项 → 检查字段 → 生成任务草案
                                   ↘ 人工审核
~~~

**Agent：**

~~~text
用户提出目标
 ↓
模型判断还缺什么信息
 ↓
选择工具查询、整理或提问
 ↓
检查结果，动态决定下一步
 ↓
达到结束条件后报告
~~~

## 如何选择？

| 场景 | 优先方式 | 原因 |
| --- | --- | --- |
| 固定格式摘要 | 单次模型调用 | 链路简单 |
| 明确的三步审批流程 | Workflow | 路径可预测 |
| 开放式问题调查 | Agent（必要时） | 需要动态决定工具和步骤 |
| 金额计算 | 普通程序 | 确定规则无需模型 |

越复杂的系统，通常越需要额外的权限管理、执行成本、失败恢复和监控。

## Agent 不等于完全自主

产品可以给 Agent 设置工具白名单、预算、最大迭代次数、人工审批和终止条件。

对删除、付款、生产变更等操作，必须有独立的授权和审查机制。

## 容易误解的地方

- 多次调用 LLM 不一定就是 Agent。
- 接入工具不意味着系统有完整规划能力。
- “自动执行”不是越多越好，先看是否可靠。
- 固定 Workflow 常常比自由规划更容易测试。

## 练习

对以下任务选择方案并解释原因：

1. 从公开文档生成 200 字摘要。
2. 按固定模板生成 PRD 并提交人工评审。
3. 在多个公开来源中调查一个技术问题，找到矛盾时继续检索。

**完成标准：** 不只会分类，还能解释复杂度、成本与验证风险。
