# 提示词怎么写？

**一句话：** 好的提示词是清晰的任务说明，不是神秘咒语。

## 六要素

```text
目标：要完成什么？
背景：已有系统和适用场景是什么？
输入：提供哪些材料？
约束：技术限制和禁止事项是什么？
输出：需要什么格式？
验收：什么结果算完成？
```

## 对比

不够清楚：“给我写一个 API。”

更清楚：

> 请为 Spring Boot 项目设计任务列表 API。使用 GET /api/tasks，支持 page 和 size。返回示例 JSON、参数说明、错误状态码和三条测试用例。先说明取舍，不要假设数据库字段。

## 可复制模板

```text
任务目标：<具体目标>
已知背景：<现有系统、技术栈>
输入材料：<已脱敏资料>
约束条件：<兼容性、安全边界>
期望输出：<结构、格式、示例>
验收标准：<可验证的条件>
信息不足时请列出假设，不要编造事实。
```

## 练习

把“帮我修复登录错误”改写成包含现象、复现步骤、期望结果、已知限制和验证方法的提示词。
