# 研发规范（建议稿）

本部分是**团队讨论稿，不代表已正式生效的公司制度**。

| 规范 | 目的 |
| --- | --- |
| [Git 与 PR](/standards/git) | 保存可审查的变更记录 |
| [API 设计](/standards/api-design) | 降低对接成本 |
| [测试与质量](/standards/testing) | 提前发现回归 |
| [发布与回滚](/standards/release) | 让变更可追溯、可恢复 |

## 规范采纳过程

1. 写清问题和建议。
2. 由执行人员评审并记录例外。
3. 试行一个迭代并记录成本。
4. 通过团队确认后标为“已采纳”。
