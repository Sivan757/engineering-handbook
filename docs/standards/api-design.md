# API 设计

**目标：** 让接口易理解、易调试、易维护。

## 设计前回答

1. 资源是什么？例如 `/api/tasks`。
2. HTTP 方法是什么？
3. 参数如何校验？
4. 谁可以访问？
5. 成功、错误和分页响应是什么？

## 示例

```http
GET /api/tasks?status=open&page=1&size=20
```

```json
{"items":[{"id":"t-1001","title":"编写文档","status":"open"}],"page":1,"size":20,"total":1}
```

## 原则

- 资源命名一致。
- 字段类型、必填条件和错误码明确。
- 区分 401 未认证与 403 无权限。
- 约定分页、限流、超时和重试。
- 对易重复提交的操作使用幂等机制。
- 使用 OpenAPI 描述并维护接口契约。

练习：设计 `POST /api/tasks` 的成功、参数错误与无权限响应。
